| 14.7 | **Action: spectral_library_match (USGS splib07 SAM matching at anomaly pixels)** 🔵 | 🟢 (completed 2026-05-13 — `app/spectral_match/` core, per-sensor cache built automatically at onboarding, full modal viewer with RGB+overlay+pulsing red dots + snap-to-pixel + L2-normalised spectrum chart + top-K side rail + materials histogram) | Identifies probable materials at anomaly pixels via Spectral Angle Mapper matching against the USGS splib07 lab library. Chains on a committed `anomaly_detection_prep`. **Not a separate service** — runs on the existing `action_run` worker queue; per-scene cost is one bounded matmul (typ. 5k–50k pixels × ~2400 library × ~150–425 bands ≈ 1–3 s CPU).<br><br>**Two-stage architecture: cache build + runtime match.** Reference theory in `spectal_match_sample/WALKTHROUGH.md`; reference impl in `spectal_match_sample/*.py` (do NOT copy — port concepts).<br><br>**Stage A — per-sensor library cache (one-time bootstrap).** The raw USGS splib07 distribution is **6.7 GB** because it ships every spectrum pre-resampled for ~20 different instruments (`_cvAVIRISc1995..2014`, `_cvASD`, `_cvBECK`, `_cvNIC`, etc.) + binary SPECPR format + GIF plots + HTML metadata + per-spectrum errorbars. **For our purposes we only need a curated subset (~40–50 MB):** the **ASD-instrument spectra from `ASCIIdata/ASCIIdata_splib07a/`** across the 7 chapter directories (`ChapterM_Minerals` 448 entries, `ChapterO_OrganicCompounds` 142, `ChapterA_ArtificialMaterials` 263, `ChapterV_Vegetation` 218, `ChapterS_SoilsAndMixtures` 103, `ChapterL_Liquids` 21, `ChapterC_Coatings` 0 ASD), plus `splib07a_Wavelengths_ASD_0.35-2.5_microns_2151_ch.txt` and one of the three ASD FWHM files (FR / HR / NG depending on which sub-instrument each spectrum was measured on — encoded in the filename's instrument tag, e.g. `ASDFRb` / `ASDHRb` / `ASDNGb`). All other instrument copies are skipped (BECK is 200–3000 nm Beckman, NIC4 is mid-IR Nicolet — wrong wavelength ranges for our hyperspectral sensors). File format per spectrum: line 1 = header `splib07a Record=<N>: <pretty name> <instrument> <product>`; lines 2–2152 = float-per-line reflectance values. USGS no-data sentinel is `-1.2300000e+034` (→ NaN before any math). Raw splib07 itself MUST be in `.dockerignore` / `.gitignore` (currently at `data/splib/`) so the 6.7 GB never enters a Docker build context. The slim curated bundle ships via a read-only `allotrope_splib07` Docker volume. A CLI builds per-sensor caches:<br>&nbsp;&nbsp;&nbsp;&nbsp;`python -m allotrope_worker.splib_cache --sensor=prisma`<br>For each sensor, the CLI loads splib07 once, Gaussian-SRF-resamples each entry onto **that sensor's native wavelength grid + native FWHMs** (PRISMA HE5, EnMAP XML, AVIRIS-NG ENVI `.hdr` — all three publish per-band FWHM), drops entries with band coverage < `min_coverage` after resampling, and persists to `<volume>/splib_cache/<sha>.npz` with an adjacent `<sha>.meta.json` listing entry names, categories, splib07 file paths, and surviving band counts. Cache key SHA-256s `(sensor_id, target_wl, target_fwhms, categories, min_coverage, splib07_version)` — any input change invalidates. Runtime memory-maps the appropriate `.npz` for the scene's sensor in sub-second.<br><br>**Stage B — runtime action.** Sensor gate: hyperspectral only with ≥ 20 surviving bands (excludes Landsat 9 + HotSat). Submit-time inputs: `input_anomaly_detection_output_id` (required when `mode="anomaly_pixels"`; references a *committed* prep's output) · `input_band_filter_output_id` (required when `mode="all_kept"`) · `categories` (splib07 sub-libraries: minerals/vegetation/soils/artificial; defaults to all) · `top_k` (positive integer, default **5**, capped at 20) · `min_coverage` (default 0.7) · `sg_window` (default 7) · `sg_polyorder` (default 2) · `mode` (`"anomaly_pixels"` default OR `"all_kept"` for full-scene material maps).<br><br>**Critical: SAM runs against the ONBOARDING vendable (native bands + native FWHMs), NOT the filtered_vendable.** The filtered cube has been linearly resampled to the 165-band common grid + PCHIP-gap-filled; for SAM that's a second pass of interpolation that erodes the very sharp absorption features splib07 matching depends on. Keep the lab→sensor resampling as the only spectral transform on the matching path.<br><br>**Worker recipe:** load the onboarding vendable + the upstream mask (or full keep mask); pull spectra at the selected pixels into `(P, B)`; drop bbl=0 / band_validity=0 bands; SG-smooth the unknowns along the band axis; memory-map the sensor's splib cache → `L (N, B)`; L2-normalise rows of both; matmul + arccos → `(P, N)` angle matrix in degrees; argpartition top-K per pixel + sort the K.<br><br>**Outputs:** `matches.parquet` (per-pixel · rank · material_name · category · angle_deg · library_file — Parquet keeps it small for large pixel sets; adds `pyarrow` to worker reqs) · `match_map.tif` (uint8 category-code raster: 0=no-match, 1=mineral, 2=vegetation, 3=soil, 4=artificial — drives the colored overlay) · `histogram.json` (sorted frequency table of best-match materials across pixels) · `summary.json` (params + counts + timing).<br><br>**Frontend viewer (modal):** three panels with linked panzoom + click-pan/zoom synchronisation. Left = RGB with anomaly pixels colored by best-match category. Middle = `match_map.tif` rendered with a category-coded LUT. Right rail = top-materials histogram (sorted, clickable to filter the overlay) + a **hover-to-preview / click-to-pin** spectrum probe: as the cursor moves over the match-map, a fixed (non-floating) side panel updates to show the hovered pixel's top-K matches as `material · category · angle` rows plus a compact uPlot chart overlaying the pixel's spectrum vs the top-5 library candidates. Clicking pins the panel until a second click. The fixed-position panel avoids hover-flicker on pan/zoom. |

## Cross-cutting items that surface as we go

These don't get their own Step number — they ride along with related work:

- **PostGIS** — currently deferred. If geographic filtering on the Scenes table needs polygon containment (not just bbox), revisit. Adds a postgres image swap.
- **Refresh-token flow** — deferred. JWT 24h is fine for v1.
- **Multiple users / roles** — `is_admin` flag is enough. Real RBAC stays deferred.
- **PostgreSQL `timestamptz` audit triggers** — defer until we need stricter audit than ORM `updated_at`.
- **Frontend code-splitting** — defer until bundle size becomes a concern.
- **Server-sent events / WebSockets for live status** — replace polling later if it becomes worthwhile. v1 is polling.
- **Preview image format migration (PNG → WebP / AVIF / tile-served COG)** 🔵 — **Deferred 2026-05-12.** All frontend-served rendered previews (color thumb, anomaly_score.png, reconstruction.png, rgb.png, nir/swir/ndvi/band_mosaic, action preview.png) are PNG today, ~1.9 MB per panel at 4096-px-long-edge — pure inheritance from matplotlib defaults, not a chosen design. PNG is bad at continuous-tone colormapped heatmap data with a masked alpha channel. Three migration ladders, in increasing reach: **(a) drop-in WebP-lossy q=85** in the same Pillow save calls (~10× smaller, ~30 lines, no new deps); **(b) AVIF q=50** for another ~30% over WebP, adds `pillow-avif-plugin`; **(c) tile-served COG** via TiTiler / maplibre-cog-protocol against the existing .tif files — biggest win for AVIRIS-NG 5592×722 strips because the frontend's pan/zoom would request only the visible tiles instead of one giant image, and unlocks client-side colormap restretch (no more "preview was baked at one p2-p98 window"). Raw .tif analytical rasters stay untouched in all three. Distinct from this roadmap's slices because it doesn't unblock any feature — it's a perf/UX win once the feature set settles.

## Risks / notable unknowns

- **Worker container size.** Once we add torch + CUDA + the existing `app/` model code, the worker image is the largest (5–10 GB). Affects bundle packaging time.
- **Onboarding multipart upload size.** EnMAP folders can be large. Need to think about Nginx/uvicorn body size limits, streaming uploads, retry on partial. Probably for Step 7c.
- **GPU availability in dev vs prod.** Dev (Mac) won't have CUDA; worker should fall back to CPU-only execution gracefully. Prod machine has the GPU. Compose should not require `--gpus all` in dev.
