\begin{solution}{ex:shapes:1}
``Eight patches, each with 165 bands, each band 128 rows by 128 columns.''

For \shape{(4, 64, 16, 16)}: \code{flatten(2)} merges the two spatial axes,
$16\times16 = 256$, giving \shape{(4, 64, 256)}; \code{transpose(1, 2)} swaps the last two axes,
giving \shape{(4, 256, 64)}. So $N = 256$ tokens, each with $64$ features. This is the stage-2 token
sequence of the encoder.
\end{solution}

\begin{solution}{ex:shapes:2}
The output is $(3-2+1)\times(3-2+1) = 2\times2$. Pair $K = \begin{pmatrix}0&1\\1&-1\end{pmatrix}$ with
each $2\times2$ block.

$(0,0)$, block $\begin{pmatrix}2&0\\1&3\end{pmatrix}$:
\begin{align*}
y_{0,0} &= 0\times2 + 1\times0 + 1\times1 + (-1)\times3 = 0 + 0 + 1 - 3 = -2.
\end{align*}
$(0,1)$, block $\begin{pmatrix}0&1\\3&0\end{pmatrix}$:
\begin{align*}
y_{0,1} &= 0\times0 + 1\times1 + 1\times3 + (-1)\times0 = 0 + 1 + 3 + 0 = 4.
\end{align*}
$(1,0)$, block $\begin{pmatrix}1&3\\0&1\end{pmatrix}$:
\begin{align*}
y_{1,0} &= 0\times1 + 1\times3 + 1\times0 + (-1)\times1 = 0 + 3 + 0 - 1 = 2.
\end{align*}
$(1,1)$, block $\begin{pmatrix}3&0\\1&2\end{pmatrix}$:
\begin{align*}
y_{1,1} &= 0\times3 + 1\times0 + 1\times1 + (-1)\times2 = 0 + 0 + 1 - 2 = -1.
\end{align*}
So $y = \begin{pmatrix}-2&4\\2&-1\end{pmatrix}$, which is what \code{F.conv2d} returns.
\end{solution}

\begin{solution}{ex:shapes:3}
$k=7$, $s=4$, $p=3$, $H=128$:
\begin{align*}
128 + 2\times3 - 7 &= 128 + 6 - 7 = 127,\\
127/4 &= 31.75,\quad \lfloor 31.75\rfloor = 31,\\
H_{\text{out}} &= 31 + 1 = 32.
\end{align*}
The stale design gives the same $32\times32$ grid as the real one, which is one reason the stale
comment never caused a visible failure; the difference is that its windows overlap by $7-4 = 3$ pixels.

$k=3$, $s=2$, $p=1$, $H=31$:
\begin{align*}
31 + 2 - 3 &= 30,\\
30/2 &= 15,\quad\lfloor15\rfloor = 15,\\
H_{\text{out}} &= 15 + 1 = 16.
\end{align*}
But $31 /\!/ 2 = 15$. The two disagree: for odd inputs this convolution rounds up, so the docstring rule
$H_{\text{out}} = H_{\text{in}} /\!/ s$ is wrong there.
\end{solution}

\begin{solution}{ex:shapes:4}
\code{nn.Conv2d(64, 160, kernel_size=3)}, from \cref{eq:shapes:convcount}:
\begin{align*}
64\times160 &= 10{,}240,\\
10{,}240\times3\times3 &= 10{,}240\times9 = 92{,}160,\\
92{,}160 + 160 &= 92{,}320.
\end{align*}
This is stage~3's patch-embedding convolution (\cref{ch:patchembed}).

\code{nn.Conv2d(32, 165, kernel_size=1)}:
\begin{align*}
32\times165\times1\times1 &= 5{,}280,\\
5{,}280 + 165 &= 5{,}445.
\end{align*}
This is Indradhanu's spectral decompressor (\cref{ch:compressor}).
\end{solution}

\begin{solution}{ex:shapes:5}
Start with $r_0 = 1$, $J_0 = 1$.
\begin{align*}
\text{layer 1 } (3,1):\quad r_1 &= 1 + (3-1)\times1 = 3, & J_1 &= 1\times1 = 1,\\
\text{layer 2 } (3,2):\quad r_2 &= 3 + (3-1)\times1 = 5, & J_2 &= 1\times2 = 2,\\
\text{layer 3 } (3,1):\quad r_3 &= 5 + (3-1)\times2 = 9, & J_3 &= 2\times1 = 2.
\end{align*}
The third layer adds twice as much as the first, although it has the same kernel, because after the
stride-2 layer its neighbouring inputs are two pixels apart.
\end{solution}

\begin{solution}{ex:shapes:6}
\code{transpose(1, 2)} turns the \shape{(1, 4, 2)} tokens into \shape{(1, 2, 4)}:
$\begin{pmatrix}1&2&3&4\\5&6&7&8\end{pmatrix}$. Laid out contiguously that is
$1\,2\,3\,4\,5\,6\,7\,8$, and \code{reshape(1, 2, 2, 2)} cuts it into channel~0
$\begin{pmatrix}1&2\\3&4\end{pmatrix}$ and channel~1 $\begin{pmatrix}5&6\\7&8\end{pmatrix}$: the
original cube.

Without the transpose, the memory of the sequence tensor is $1\,5\,2\,6\,3\,7\,4\,8$, and the reshape
gives channel~0 $\begin{pmatrix}1&5\\2&6\end{pmatrix}$ and channel~1
$\begin{pmatrix}3&7\\4&8\end{pmatrix}$: each ``channel'' now mixes both real channels. The shape is
right and the data are scrambled.
\end{solution}
