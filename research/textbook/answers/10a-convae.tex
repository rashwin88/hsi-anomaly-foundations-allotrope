\begin{solution}{ex:convae:1}
With $k=4$: $(16-1)\times2-2\times1+4=30-2+4=32$, an exact doubling. With $k=3$: $30-2+3=31$, one short. That is why
the code uses $k=4$ for the transposed convolutions (and its comment says $k=3$ ``would require output\_padding''). A
CPU check gives $32\times32$ and $31\times31$ \tagC.
\end{solution}

\begin{solution}{ex:convae:2}
Encoder channels $1\to16\to32\to64$, by \cref{eq:convae:stage}:
\begin{align*}
1\to16 &: 16\times1\times16+3\times16 = 256+48 = 304\\
16\to32 &: 16\times16\times32+3\times32 = 8{,}192+96 = 8{,}288\\
32\to64 &: 16\times32\times64+3\times64 = 32{,}768+192 = 32{,}960\\
\text{encoder} &: 304+8{,}288+32{,}960 = 41{,}552
\end{align*}
Decoder channels $64\to32\to16\to1$, the last without BatchNorm:
\begin{align*}
64\to32 &: 32{,}768+96 = 32{,}864\\
32\to16 &: 8{,}192+48 = 8{,}240\\
16\to1 &: 16\times16\times1+1 = 257\\
\text{decoder} &: 32{,}864+8{,}240+257 = 41{,}361
\end{align*}
Total $41{,}552+41{,}361=82{,}913$; building the class gives the same \tagC.
\end{solution}

\begin{solution}{ex:convae:3}
Four stages divide each side by $2^4=16$: $256/16=16$. The bottleneck is $256\times16\times16=65{,}536$ values; the
input is $256\times256=65{,}536$. Exactly as many, at every patch size: the first stage multiplies the count by 8 (1
channel becomes 32 on a quarter of the area) and each later stage halves it (channels double, area quarters), so
$8\times\tfrac12\times\tfrac12\times\tfrac12=1$. The bottleneck is no compression at all.
\end{solution}

\begin{solution}{ex:convae:4}
A valid, hidden pixel has $m_\text{valid}=1$, $m_\text{input}=0$. Asanskrita: channel 0 is $30\times1\times0=0$, so
$(0,1,0)$. Drashta: the masks are applied first, then the normalisation, so channel 0 is
$(0-24.5756)/13.5744=-1.8104$: $(-1.8104, 1, 0)$. The true 30\,°C appears in neither.
\end{solution}

\begin{solution}{ex:convae:5}
Pratibimba was trained to reproduce whole patches with nothing hidden, so it never learned what to do with pixels set
to 0\,°C. The product's checkerboard hides every other pixel at inference, a patch unlike anything it trained on, and
it reconstructs the whole field badly.
\end{solution}

\begin{solution}{ex:convae:6}
$x_0=3$ at position 0 adds $(3,6,6,3)$ to positions 0--3; $x_1=-1$ at position 2 adds $(-1,-2,-2,-1)$ to positions
2--5. Sum: $(3,\ 6,\ 6-1,\ 3-2,\ -2,\ -1)=(3,6,5,1,-2,-1)$. Crop one from each end: $(6,5,1,-2)$. PyTorch's
\code{ConvTranspose1d} gives the same \tagC.
\end{solution}
